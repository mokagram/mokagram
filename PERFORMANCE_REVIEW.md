# Аудит производительности и узких мест mokaGram (Performance Review)

## Топ-3 самых тяжелых мест в проекте

1. **Синхронный Python GIL в GUI-потоке (`mokagram_plugin_api.cpp` / `mokagram_plugins.cpp`)**
   - **Что делает:** При рендере и прокрутке сообщений клиент синхронно вызывает `CallTextHook`, `CallBadgeHook` и `HiddenByPlugin`.
   - **Чем опасно:** Главный поток Qt блокируется на ожидании GIL (`const auto gil = Gil()`). Если воркер в фоне обрабатывает пакет обновления MTProto через Python, интерфейс зависает намертво (дроп FPS до нуля).

2. **Холодный старт и отложенный фриз (`call_delayed(300)` в `application.cpp`)**
   - **Что делает:** Через 300 мс после старта окна вызывается `Plugins::StartEngine()`, который подгружает Python DLL, компилирует встроенные модули и парсит гигантский JSON `tl_schema.inc` (1.7 МБ).
   - **Чем опасно:** Клиент визуально открылся, но как только юзер кликает по чату — приложение ловит секундный лаг.

3. **Софтверные эффекты на CPU (`effects/mokagram_effects.cpp`)**
   - **Что делает:** Эффект рассыпания сообщений (`PlayDelete`) режет картинку на 500 кусочков и симулирует физику на CPU каждый кадр через `QPainter`. Анимированные обои чата непрерывно декодируют видео через CPU-кодек.
   - **Чем опасно:** Загрузка ядер CPU до 100%, перегрев, быстрый разряд батареи на ноутбуках.

## Детальный разбор по категориям

### 1. Медленная загрузка (Старт приложения)
- **Инициализация Python:** парсинг `tl_schema.inc` (1.7 МБ) и запуск `_fw_load_all()` на старте.
- **Музыкальная библиотека `library.json`:** при старте с диска целиком парсится монолитный JSON с историей на 3000 треков и 1500 id показов.
- **SQLite база анти-удаления (`history.db`):** при больших базах запуск WAL-журналирования создает I/O всплеск на диске.
- **SSE-поток и спам сети:** в `mokagram_misc.cpp` таймер каждые 3 секунды дергает `Refresh(0)` до момента коннекта к серверу.

### 2. Нагрузка во время работы (CPU / Фризы / 1% Low FPS)
- **Хуки сообщений на главном потоке:** Сериализация `QJsonObject` в строку + маршалинг в Python + захват GIL на каждое видимое сообщение.
- **Частицы при наборе текста:** каждый символ генерирует всплеск искр/звезд с физикой на CPU.
- **Кастомные формы аватарок:** построение `QPainterPath` с десятками кривых Безье (звезды, цветы, капли) при быстром скролле списка диалогов.
- **Spotify Canvas в музыке:** фоновое скачивание и декодирование зацикленного видео HLS/MP4 в плеере.
- **Кэш анти-удаления `MediaMem`:** хранит до 4000 полных бинарных дампов пакетов MTProto прямо в памяти.

### 3. Сборка на VPS (Время и RAM билдера)
- **Файл `tl_schema.inc`:** 1.7 МБ включается в `mokagram_plugins.cpp`. Память компилятора (`gcc`/`clang`) взлетает до **3.5–4.5 ГБ на 1 поток** компиляции. Если на VPS мало RAM — процесс прибивает Linux OOM Killer.
- **Монолит `mokagram_music_ui.cpp`:** 358 КБ C++ кода в одном файле компилируется по несколько минут.
- **WebRTC (`lib_webrtc`):** забирает до половины времени полной сборки tdesktop.

## Что нужно настроить для быстрой сборки на VPS:
1. **SWAP файл минимум 8–16 ГБ:**
   ```bash
   sudo fallocate -l 12G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
   ```
2. **Ограничить параллелизм `ninja`:** не запускать `ninja` без флагов, рассчитывать 1 поток на каждые 2.5–3 ГБ оперативной памяти:
   ```bash
   # Например, для 8 ГБ RAM:
   ninja -j 2
   ```
3. **Включить `ccache`:** экономит 80-90% времени при повторных сборках.
