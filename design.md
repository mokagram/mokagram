# Дизайн mokaGram

Как выглядит клиент и как собрать новый экран так, чтобы он выглядел своим. Основа: Material 3 в формах и состояниях (крупные скругления, пилюли, тональные поверхности, переключатель M3), цвета и шрифты берутся из темы Telegram. Это не спецификация M3 целиком: берём из неё то, что уже есть в общих деталях окон, и не придумываем своё.

## Айдентика

### Характер

- Тёмный, спокойный, плотный интерфейс рабочего стола. Один главный объект на экране, остальное тише.
- Скруглённые поверхности собирают связанное в группы, между группами воздух.
- Акцент только для выбора и главного действия. Вторичный текст, время и подписи тише основного.
- Никаких декоративных эффектов ради эффекта: градиентов, теней, стекла, рамок, если их нет в эталонном окне.

### Цвет

Цвет всегда через семантические токены палитры (`st::windowBg`, `st::windowFg` и т.д.), а не через hex в коде экрана. Тему выбирает пользователь, поэтому экран обязан нормально выглядеть и в светлой. Значения ниже: тёмная тема, в которой клиент показывают и проверяют.

| Роль | Токен | Тёмная тема |
| --- | --- | --- |
| Фон окна (подложка под карточками) | `boxBg` | `#1c1c1c` |
| Карточка, поле, кнопка-кружок | `windowBg` | `#282828` |
| Наведение | `windowBgOver` | `#323232` |
| Основной текст | `windowFg` | белый |
| Подписи, время, второстепенное | `windowSubTextFg` | `#8e8e93` |
| Акцент: главная кнопка, выбор, ссылки | `windowBgActive`, `windowActiveTextFg` | `#0a84ff` |
| Фон чата | обои темы | `#151515` |

Фирменные цвета сторонних сервисов допустимы только в их значке (оранжевый SoundCloud `#ff5500`), не в рамках и кнопках.

### Форма

| Элемент | Правило | Где в коде |
| --- | --- | --- |
| Окно | радиус 28 | `BoxParts::kBoxRadius`, `Plugins::RoundedWindow` |
| Карточка | радиус 22, не больше половины высоты | `BoxParts::kCardRadius`, `BoxParts::PaintCard` |
| Кнопка шапки (закрыть, назад, меню) | круг 36, фон карточки | `Plugins::MakeHeaderButton`, `BoxParts::MakeRoundButton` |
| Кнопка | пилюля, высота 40 (в строке) или 44 (главная на всю ширину) | `BoxParts::PillActive`, `PillLight`, `PillAttention` |
| Поле ввода | в карточке, без рамки, высота от 44 | `BoxParts::CardField` |
| Переключатель | M3, 40 × 24, бегунок растёт при включении, 200 мс | `BoxParts::MakeSwitch` |
| Аватар, значок сервиса | круг; значок приложения скруглённый квадрат 24% | |

Отступ карточки от края окна 14, внутренние поля карточки 16, между карточками 8.

### Значки

- Значки интерфейса только из пака iOSTelegram. Список пака клиент печатает строками `PACK ...` в stderr при запуске с `MOKAGRAM_DEBUG_CMD=1` и команде `customize`. Сверять по списку, не угадывать.
- Свои значки не рисовать, стилевые значки tdesktop вместо пака не подставлять.
- Логотип стороннего сервиса берётся настоящий (контур из simple-icons, CC0) и рисуется через `QSvgRenderer`, как `PaintSoundCloudBadge` в `music/mokagram_soundcloud_login.cpp`.
- Если у сущности есть картинка (аватар профиля, обложка), показывать её, а значок сервиса ставить маленьким в угол.

### Текст

Коротко и по-человечески. Заголовок окна 2-4 слова, пояснение одно-два предложения, на кнопке глагол. Длинных тире нет. Каждая строка интерфейса идёт через `Mokagram::Lang::Tr("...")` и получает английский перевод в `mokagram/lang/mokagram_lang_table.inc`.

## Эталоны

Новое окно не придумывается, а собирается по одному из готовых:

- **«Информация о сообщении»** (`msginfo/mokagram_message_info.cpp`): шапка с крестиком слева и названием по центру, карточка со строками, главная пилюля 44 на всю ширину внизу. Эталон для любого простого окна.
- **«Плагины»** (`plugins/mokagram_plugin_install.cpp`): список карточек с переключателями, круглые кнопки шапки.
- **Вход в SoundCloud** (`music/mokagram_soundcloud_login.cpp`): карточка со значком и строкой статуса, две пилюли, скрытая карточка ручного ввода.
- **Музыка** (`music/mokagram_music_ui.cpp`): схема в [docs/design/moka-music.svg](docs/design/moka-music.svg), общий лист элементов в [docs/design/moka-identity.svg](docs/design/moka-identity.svg). Схемы составлены по коду и не заменяют проверку в клиенте.

## Как собрать экран в стиле M3

1. **Найти эталон.** Выбрать ближайшее окно из списка выше и открыть его код. Раскладку брать оттуда, а не из памяти.
2. **Каркас.** `Box([=](not_null<Ui::GenericBox*> box) { ... })`, первым делом `Plugins::RoundedWindow(box)`. Стандартные кнопки бокса (`addButton`, `addLeftButton`) не использовать: три кнопки внизу не влезают и налезают друг на друга.
3. **Шапка.** `RpWidget` высотой 40 с отступами 10, слева `Plugins::MakeHeaderButton(header, true, close)`, по центру `FlatLabel` со стилем `st::boxTitle`, позиции пересчитывать в `widthValue()`.
4. **Содержимое в карточках.** `VerticalLayout` с отступом 14 по бокам и `paintOn` → `BoxParts::PaintCard`. Один смысл = одна карточка. Подписи `st::boxDividerLabel`, основной текст `st::boxLabel`; центрированный текст через копию стиля с `align = style::al_top`.
5. **Статус внутри экрана.** Ход действия («Ищу…», «Проверяю…», ошибка) пишется в строку карточки, а не тостом и не новым окном.
6. **Действия.** Главное действие: пилюля `defaultActiveButton` высотой 44 на всю ширину (`setFullWidth` в `widthValue()`). Второе действие: такая же пилюля на `PillLight`. Больше двух пилюль подряд не ставить, редкое прятать.
7. **Редкое и ручное.** Прятать в `Ui::SlideWrap<Ui::VerticalLayout>` и раскрывать `toggle(true, anim::type::normal)` по второй пилюле или при ошибке автоматики.
8. **Списки и настройки.** Переключатель `BoxParts::MakeSwitch`: в настройках клик обрабатывает вся строка, в плагинах сам переключатель. Наведение `windowBgOver`, выбор акцентом.
9. **Пиксели.** Любой размер в C++ через `style::ConvertScale(n)`. Геометрию списка сообщений ради визуала не менять, рисовать поверх.
10. **Строки.** Каждая новая строка в `mokagram_lang_table.inc` с английским переводом.

## Состояния

Каждый интерактивный элемент различает обычное, наведённое, нажатое, фокус клавиатуры, недоступное и выбранное состояния. Действие, которое меняет что-то важное (отключить аккаунт, удалить), срабатывает только по своей кнопке, а не по клику в любом месте строки. Анимация показывает смену состояния и не задерживает действие; с выключенными анимациями результат должен оставаться понятным.

## Проверка перед «готово»

1. Масштаб 100% и `-scale 150`.
2. Скриншот того же состояния, которое увидит пользователь: живой чат с перепиской, не пустой сервисный.
3. Тёмная и светлая темы, длинные строки на русском и английском, узкое окно.
4. Все состояния из раздела выше, включая ошибку и пустое.
5. Закрыть окна и меню, открытые отладкой.
